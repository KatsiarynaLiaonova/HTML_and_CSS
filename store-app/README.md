# ALI BABA 3.0.0

Программа локального учета магазина ALI BABA для Windows 10/11 x64 и macOS. Запускается отдельным окном с ярлыка; вкладка браузера не нужна. Интерфейс: русский, английский, арабский с RTL. Данные хранятся в SQLite на компьютере; интернет для работы не требуется. Доступен локальный режим одной кассы и общая база для двух касс с учетными записями владельца и кассиров. Налоги и смешанная оплата не реализованы.

Подключение двух Windows-касс и Mac, работа без интернета в магазине и удаленный доступ: [пошаговая инструкция](NETWORK-SETUP.md).

В общей версии база находится на главной кассе: она и локальная сеть должны работать. Mac из другого места подключается через Tailscale. Установка программы сама по себе не настраивает сеть и не переносит данные между компьютерами.

## Обновление Nile Store до ALI BABA без потери товаров

1. В старой программе нажмите «Резервная копия» и сохраните файл отдельно, желательно вне компьютера.
2. Закройте кассовую смену. Завершите старую программу кнопкой «Stop / Завершить»; при запуске через Терминал нажмите `Control + C`. Закройте старую вкладку браузера.
3. Установите новую сборку ALI BABA либо запустите установщик свежих исходников, как описано ниже. **Не удаляйте папку данных `.retail-store` в вашем профиле.**
4. Запустите **ALI BABA**, проверьте номер **3.0.0** в «Настройках» и наличие товаров, остатков, партий и старых чеков.
5. Перед обновлением формата базы автоматически создается `before-upgrade-…sqlite`. Старые чеки сохраняют прежнее название магазина. В настройках название по умолчанию NILE меняется на ALI BABA; ваше собственное ранее заданное название сохраняется.
6. Старый значок Nile Store можно убрать после проверки новой версии. Для запуска используйте новый значок ALI BABA.

Обновление **не очищает тестовые продажи**. Для проверки на чистой базе используйте другую папку `STORE_DATA_DIR`. После перехода на формат базы 4 старую версию программы не запускайте. Для отката нужны отдельная копия `before-upgrade` и соответствующая старая версия. Если обновляетесь с первой версии, перед продажей откройте смену и укажите фактический размен; старые продажи остаются в отчетах и не попадают в новую смену.

## Установка и запуск отдельным окном

### Готовая программа — Python не нужен

GitHub → **Actions → Build ALI BABA desktop → успешный запуск для новой версии → Artifacts**. Сборки из старого запуска Actions не обновляются автоматически.

- **Windows X64**: распакуйте архив, запустите `AliBaba-Setup-Windows.exe`. Установщик создает значки ALI BABA на рабочем столе и в меню «Пуск». Двойной щелчок открывает отдельное окно программы. Требуется **Microsoft Edge WebView2 Runtime**, обычно уже установленный в Windows 10/11. Если движок отсутствует, установите Evergreen Runtime с официальной страницы Microsoft: https://developer.microsoft.com/microsoft-edge/webview2/ . Для его первоначальной установки может потребоваться интернет. В дальнейшем сам магазин работает без интернета. Удаление программы сохраняет базу в профиле.
- **macOS ARM64**: для Mac с Apple Silicon (M1/M2/M3/M4 и новее).
- **macOS X64**: для Mac с Intel. В архиве — `ALI BABA.app`; перенесите ее в «Программы». Встроенный движок окна — системный WKWebView.

Внешний браузер не открывается: интерфейс, печать и выбор файлов работают внутри окна ALI BABA. В локальном режиме и на главной кассе при закрытии окна программа останавливает службу и делает резервную копию. Подключенный клиент завершает только свое соединение; общая база остается на главной кассе. Повторный запуск при уже работающей программе сообщает об этом; переключитесь в существующее окно. Язык в новом окне может понадобиться выбрать заново — товары от этого не меняются.

Для скачивания Artifacts может потребоваться вход в GitHub. Сборки пока не подписаны коммерческим сертификатом и не нотарифицированы Apple. На Mac после попытки запуска: «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть», если вы доверяете источнику. Windows также может показать предупреждение о неизвестном издателе.

**Нативное окно, загрузка файлов и физическая печать требуют проверки на вашем Windows/Mac.** В CI предусмотрены проверки запуска окна исходников и готовой сборки; наличие этих команд в репозитории само по себе не означает, что соответствующая сборка уже прошла проверку.

### Установка из исходников, с Python 3.10+

Официальный Python с python.org включает Tkinter для окна установки. При первоначальной установке и обновлении нужен интернет для загрузки `pywebview` и системных Python-компонентов окна. Установщик создает отдельную Python-среду приложения, не меняя пакеты других программ.

- **Mac**: распакуйте свежие исходники и запустите `Install-Mac.command` из `store-app`. Если Finder не запускает `.command`, откройте Терминал в папке `store-app` и выполните `bash Install-Mac.command`. Нажмите **Install / Update**. Установщик создаст `~/Applications/ALI BABA.app` и откроет эту папку. Дальше используйте ее значок. Установленный Python должен оставаться на компьютере.
- **Windows**: запустите `Install-Windows.cmd` и нажмите **Install / Update**. Исходники и отдельная среда копируются в `%LOCALAPPDATA%\ALI BABA`; создаются значки на рабочем столе и в меню «Пуск».
- Для обновления из исходников сначала завершите предыдущую программу и снова запустите установщик из свежего ZIP. Данные находятся отдельно и сохраняются.

Для разработчика после `python -m pip install -r requirements-desktop.txt`: `python desktop.py`. Файлы `start-mac.command` / `start-windows.bat` также запускают отдельное окно через Python текущей системы; в нем должны быть установлены desktop-зависимости.

Резервный режим через браузер остается доступен: `python3 server.py` (Mac) / `py -3 server.py` (Windows). Без автоматического браузера: `python3 server.py --no-browser`. По умолчанию порт 8765; другой порт: `--port 8766`. Локальная служба доступна только на текущем компьютере. Оконную программу и браузерный сервер одновременно не запускайте.

## Товары, партии и закупки

Создайте товар: название как оно должно печататься, единица (шт. / кг), продажная цена USD, минимальный остаток. Штрихкод производителя можно ввести сканером; пустое поле создает собственный восьмизначный код. Название, код, цену и минимум можно менять; единица после создания фиксируется. Старые чеки не меняются.

Каждое поступление — новая партия с количеством, закупочной ценой за штуку / кг **в EGP**, поставщиком и номером документа. Поставщики повторно предлагаются при вводе. FIFO идет по времени поступления и номеру партии. Программа показывает закупочные цены каждой партии и их пересчет в другие валюты.

Список «Пора заказать» показывает товары с остатком не выше минимума, включая нулевой остаток. Доступен CSV. Стоимость склада EGP = сумма оставшихся количеств партий × их закупочные цены.

## Инвентаризация и списания

- **Пересчет**: введите фактический остаток и причину. Недостача списывается по FIFO. Для излишка укажите закупочную цену EGP: создается отдельная партия.
- **Списание**: введите количество к списанию и причину (например, повреждение или собственное использование).
- Нулевой фактический остаток допустим. Отрицательные остатки запрещены. Если остаток успел измениться после открытия экрана, операция отклоняется: обновите экран и пересчитайте.
- Журнал сохраняет поступления, продажи, отмены, возвраты, пересчеты и списания. Складские потери показаны в журнале; они не входят в показатель валовой прибыли **от продаж**.

## Кассовые смены

Откройте смену, введя фактический размен отдельно для USD/EUR/EGP/RUB. Разрешена одна открытая смена на каждой кассе. В общей версии деньги и размен двух касс учитываются отдельно; остатки общие. Продажи без открытой смены блокируются.

Ожидаемые наличные = размен + наличные продажи − отмены наличных продаж − наличные возвраты + внесения − изъятия. Внесения / изъятия оформляются с причиной. Карта EGP и переводы RUB показаны отдельно и не увеличивают ящик наличных.

При закрытии пересчитайте каждую валюту. Программа покажет ожидаемую сумму, фактическую и расхождение. Итог закрытой смены сохраняется неизменным, можно выгрузить CSV. Автоматически создается резервная копия.

## Продажи, оплата и отмена ошибки

Сканер QW2100 должен работать как USB-клавиатура с Enter после кода. Сфокусируйте поле сканирования либо найдите товар по названию. Для весового товара введите вес до 0,001 кг.

Сканирование доступно в трех местах:

- **Касса:** щелкните поле сканирования и считайте штрихкод. Enter добавляет найденный товар в чек; повторное сканирование увеличивает количество. Неизвестный код не создает товар и не записывает продажу.
- **Новая карточка товара:** кнопка сканирования переводит курсор в поле штрихкода. Считайте код производителя, затем заполните название, единицу и цену и сохраните карточку. Enter от сканера не должен сохранять незаполненную карточку.
- **Поступление на склад:** считайте код в отдельном поле поступления. Программа выберет существующий товар и переведет курсор на количество. Затем укажите количество, закупочную цену и при необходимости поставщика/накладную; сохраните поступление. Само сканирование остаток не меняет. Для неизвестного кода доступно явное создание карточки с уже заполненным штрихкодом.

Сканер не взвешивает товар: вес в кг вводится отдельно. Если после сканирования ничего не происходит, проверьте фокус поля и настройку суффикса Enter/CR в руководстве именно вашей модели сканера. Последовательность настройки разными служебными штрихкодами зависит от модели.

| Валюта | Наличные | Карта | Перевод |
|---|---|---|---|
| USD | Да | — | — |
| EUR | Да | — | — |
| EGP | Да | Да | — |
| RUB | Да | — | Да |

Скидки в процентах / суммой доступны для строки и всего чека. Фиксированная скидка — в валюте оплаты; перепроверьте ее при смене валюты. Наличные: сдача в той же валюте; пустое поле полученной суммы означает точную оплату. Для перевода кассир подтверждает получение. Банковского подключения нет.

В отчетах доступна **отмена ошибочного чека**, пока открыта смена. Укажите причину и подтвердите, что деньги уже возвращены отдельно. Программа **не отправляет банковский возврат**. Исходный чек сохраняется, товар возвращается в исходные партии FIFO. Повторная отмена запрещена.

В отчет добавляется отрицательная корректировка **на дату отмены**, с исходными курсами. Старая продажа остается на исходную дату. Деньги корректируются в текущей смене, итог прошлой закрытой смены остается прежним. Если банк / сервис не вернул комиссию, она остается расходом. После частичного возврата отмена всего исходного чека блокируется; оставшиеся товары можно вернуть отдельными операциями.

## Частичный возврат покупателю

В «Отчетах» найдите исходную продажу и нажмите **«Вернуть товары»**. Выберите позиции и количество: для штук — целое число, для кг — до 0,001. Укажите причину. Флажок **«Можно снова продавать»** включен по умолчанию; снимите его для поврежденного товара, который нельзя снова продавать.

Предварительный расчет показывает сумму в **исходной валюте и по исходному способу оплаты**, с учетом скидки каждой строки и скидки всего чека. Текущие цены и курсы на возврат не влияют. Копеечный остаток распределяется так, чтобы последовательные частичные возвраты не превысили сумму исходной покупки. Повторно вернуть уже возвращенное количество нельзя.

Верните деньги покупателю отдельно и подтвердите это в форме. Приложение **не отправляет банковские возвраты**. Если банк фактически вернул часть комиссии, укажите именно эту сумму; по умолчанию возврат комиссии равен нулю. Сумму комиссии указывайте при оформлении возврата товара: отдельная операция для более позднего возмещения комиссии пока не предусмотрена.

Возврат требует открытой смены. Он уменьшает соответствующие платежи текущей смены; наличный возврат уменьшает ожидаемые наличные в исходной валюте. Итог прошлой закрытой смены остается прежним. В отчете появляется отдельная отрицательная операция на дату возврата, с исходными курсами. Исходный чек не изменяется.

При возврате на склад товар попадает в те партии, из которых он был продан; восстанавливается соответствующая себестоимость. Для поврежденного товара продаваемый остаток не увеличивается, а его исходная себестоимость остается расходом продажи. Возвращать остаток покупки можно несколькими операциями. Для обмена оформите возврат и отдельную новую продажу.

## Валюты, округление и комиссии

Курс — количество единиц EUR/EGP/RUB за **1 USD**. До первой продажи сохраните реальные курсы; исходные единицы — заглушки. Закупочная цена EGP и продажная цена USD фиксированы; остальные отображения пересчитываются.

Перед изменением курса или округления открывается таблица старых и новых цен. После подтверждения изменившиеся ценники попадают в список замены. История продаж не пересчитывается.

Округление задается отдельным шагом для EUR/EGP/RUB (например, 0,50, 1 или 5). До ближайшего шага, ровно половина — вверх. USD фиксирован до центов. Округляется **цена за единицу** одинаково на ценнике и кассе, затем сумма строки до центов, скидка строки и скидка чека. Весовая покупка может иметь дробную итоговую сумму даже при округленной цене за кг.

Комиссии карты (EGP) и переводов (RUB): процент и фиксированная сумма за платеж. Это расход магазина; сумма покупателя не увеличивается. Правило и комиссия сохраняются в продаже. Изменение настроек не меняет старые продажи. При нулевом чеке комиссия равна нулю.

## Отчеты

Период включительно по локальному времени компьютера, фильтры валюты и способа оплаты, независимая валюта отображения (по умолчанию EGP), CSV.

- Выручка после скидок.
- Себестоимость по реально списанным партиям FIFO.
- Валовая прибыль = выручка − себестоимость.
- Комиссии.
- Прибыль после комиссий = валовая прибыль − комиссии. Это не чистая прибыль: аренда и другие расходы не учтены.

Пересчет каждого события использует **курс на момент исходной продажи**. Отмена видна отдельной строкой; при попадании продажи и отмены в период их выручка и себестоимость взаимно погашаются. Комиссия погашается только при подтвержденном возврате комиссии. Старые продажи первой версии имеют нулевую комиссию и не привязаны к сменам.

## Чеки и массовые ценники

XP-233B: начальный размер **38 × 25 мм**. XP-N160II: измеренная лента около 78 мм, начальная полезная ширина чека 70 мм. Размеры и название магазина меняются в настройках и входят в копию базы.

Для этикеток **ширина измеряется поперек ленты**, параллельно линии отрыва, а **высота — вдоль подачи бумаги**. Для ленты 38 мм поперек и шага этикетки 25 мм сохраняйте 38 × 25 мм. Настройка **«Поворот печати ценника»** отдельно задает 0°, 90° влево/вправо или 180°. Размер выходной страницы при любом повороте остается равным измеренной этикетке. При четверти оборота меняются размеры внутреннего макета, чтобы содержимое поворачивалось без обрезки и без автоматической смены ориентации бумаги драйвером. Настройка относится только к ценникам, чековая лента не поворачивается.

В настройках нажмите **«Пробная этикетка»**: она показывает «ВЕРХ», «НИЗ», «ЛЕВО», «ПРАВО» и использует текущие поля даже до сохранения. Проба доступна без товаров и настроенных курсов; она не меняет остатки и не подтверждает замену ценников. Если верх макета выходит у правого края бумаги, начните проверку с **90° влево** и одной этикетки. Сохраните настройку после удачной физической пробы. Программная проверка PDF не заменяет проверку вашего драйвера XP-233B и реальной подачи бумаги.

В «Ценниках» выберите количество копий каждого товара либо заполните по остаткам (для кг — одна этикетка). Можно печатать только требующие замены. Не более 1000 этикеток за операцию, каждая на отдельной странице. После успешной печати нажмите **«Подтверждаю, что этикетки напечатаны»**. При отмене печати закройте окно — отметки сохранятся. Подтверждение означает замену всех старых ценников этого товара; программа не проверяет физическую замену.

Печать через системный диалог браузера, на Mac можно сохранить PDF. Масштаб 100%, колонтитулы отключены, бумага в драйвере соответствует шаблону. Обычные подробные чеки, без налоговой интеграции. Code 39 кодирует латинские заглавные буквы и цифры; код производителя при печати также представлен в Code 39. Длинный код на маленькой этикетке может не считываться — увеличьте ширину и проверьте сканером.

**USB-оборудование, арабская физическая печать, подача этикеток и Windows/macOS-инсталляция требуют проверки на вашем компьютере.** Linux-проверки и автоматические сборки не заменяют ее.

## Резервные копии и восстановление

Данные: `~/.retail-store/store.sqlite` (на Windows `.retail-store` в профиле). Они не лежат в папке приложения. Для изолированной тестовой базы — `STORE_DATA_DIR` на другую папку.

Копии создаются при запуске, раз в 24 часа непрерывной работы, при закрытии смены, при завершении через окно приложения и вручную. Локальные копии: `.retail-store/backups`. Дополнительно укажите **существующую** папку внешнего диска или уже синхронизируемую облачную папку. В оконной версии доступен выбор папки. Программа не подключает облачный аккаунт сама. При недоступности диска сохраняется локальная копия и выводится предупреждение. Старые копии автоматически не удаляются.

Кнопка «Скачать файл копии» сохраняет SQLite средствами браузера. Восстановление: закройте смену → «Настройки» → выберите `.sqlite` → введите `RESTORE`. Проверяются формат, целостность и версия, затем создается локальная страховочная копия `before-restore-…sqlite`. Все текущие данные заменяются выбранной копией; шаблон печати восстанавливается тоже. Язык интерфейса хранится отдельно в браузере. Перед реальной работой проверьте восстановление на отдельной тестовой базе.

## Проверки и сборка для разработчика

Установите зависимости `python -m pip install -r requirements-desktop.txt` в отдельной виртуальной среде.

```sh
python3 -m unittest discover -s tests -v
python3 desktop.py --self-test
```

Браузерный сценарий `tests/browser.cjs` требует Playwright и Chromium; запускайте только против **пустой изолированной** базы на порту 8767 (скрипт создает продажи и восстанавливает базу). Не направляйте его на рабочие данные.

```sh
STORE_DATA_DIR=/tmp/ali-baba-browser python3 server.py --no-browser --port 8767
node tests/browser.cjs
```

Дополнительные сценарии Playwright `tests/printing.cjs` и `tests/scanner.cjs` запускаются тем же способом, каждый против отдельной **пустой** базы. Проверка печати сохраняет PDF всех четырех поворотов, двух копий ценника и обычного чека; проверяет размеры страниц, границы макета и отсутствие лишних страниц. Проверка сканирования имитирует ввод USB-клавиатуры со штрихкодом и Enter во всех трех сценариях. Подключение физического USB-сканера проверяется на кассовом компьютере отдельно.

Для оконного self-test установите зависимости: `python -m pip install -r requirements-desktop.txt`. Проверка настоящего окна на Windows/macOS: `python desktop.py --desktop-smoke-test` (создает отдельную временную базу).

Сборка на целевой ОС: `python -m pip install -r requirements-desktop.txt pyinstaller==6.16.0`, затем из `store-app`: `python -m PyInstaller packaging/NileStore.spec --noconfirm`. На Windows установщик собирается Inno Setup 6 из `packaging/windows-installer.iss`. CI проверяет расчеты, миграцию, HTTPS, роли, две кассы, браузерные сценарии и запуск отдельного окна исходников/готового приложения, включая вход в общую базу через `--shared-desktop-smoke-test`; файлы публикуются как Artifacts. Автоматическое обновление из интернета не включено.
